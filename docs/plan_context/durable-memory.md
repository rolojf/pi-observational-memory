Upstream seams identified before implementation:

- At the inspected upstream base, `src/agents/reflector/agent.ts` `runReflector()` had a fixed prompt/tool list and returned `Reflection[] | undefined`. It sees a bounded observation/reflection slice, not the complete conversation. An existing `agentLoop` injection is a test seam, not a durable-memory integration API.
- `src/agents/reflector/prompts.ts`: preserve this upstream prompt; add feature-specific guidance separately, scoped to the additional outputs.
- `src/hooks/consolidation-trigger.ts`: owns model fallback, cancellation, reflection append, and the same-run reflection gate for dropper maintenance. Its existing optional hook only runs after idle consolidation; it cannot add outputs to the reflector's own reasoning pass.
- `src/session-ledger/worker-memory.ts`: worker input is budgeted. Do not promise complete capture of every decision or expand this budget to make exports exhaustive.
- `src/index.ts`: registration/wiring. `scripts/build.js` bundles this entry into committed `dist/index.ts`.
- `tests/reflector.test.ts` and `tests/consolidation-trigger.test.ts`: existing fake-loop and stage tests to extend or reuse without replacing upstream coverage.

## 2. Proposed first-version defaults

These are implementation proposals, not additional user requirements:

- Durable memory defaults to on in any session directory. Capture is automatic on each actual reflector run; no approval is requested for each record.
- By default, use the Git worktree root when available and otherwise the session cwd. Root discovery asks Git with a bounded timeout rather than treating any `.git` directory as a valid worktree. An explicit root must contain the session cwd and stay inside its Git worktree when one exists.
- Opt out only in the session cwd's `.pi/settings.json` with `"durable-memory": false` or the existing object form with `enabled: false`. Agent-directory settings supply defaults for the optional `projectRoot` and read-only `sharedMemoryRoot` paths, which local settings can override. Malformed configuration still prevents capture with a diagnostic.
- Write project decisions to `ADR.jsonl` and technical lessons to `MEMORIES/`. Use existing shared-memory metadata for retrieval only when configured/in scope; automatic writes or promotion into `$HOME/MEMORIES/` are deferred. Do not inspect other projects to prove generality during reflection.
- Match literal repository-relative file paths initially. Globs, symbols, and rename tracking are deferred.
- Keep capture cadence, passive mode, idle-mode behavior, worker limits, and model selection unchanged. A short session that never reaches a reflector run will not automatically export its decisions; a forced shutdown flush is not part of this version.

## 3. Small data contracts

### ADR.jsonl

One ordinary JSON object per physical line, serialized by code:

```ts
type DecisionRecord = {
  id: string;                         // generated by code; no external UUID tool
  date: string;                       // timezone-aware capture timestamp
  who: "user" | "agent+user" | "agent"; // reflector's attribution, not verified
  files: string[];                    // repository-relative paths
  decision: string;
  reason?: string;
};
```

The enum generalizes the original design's person-specific labels without losing their meaning. `date` is when the record was captured, not a claim about the exact time the original decision was made. Display that distinction. Keep `reason` when the reflector provides one; no required evidence, alternatives, lifecycle status, or supersession fields. Do not fabricate empty status machinery.

Use `JSON.stringify(record) + "\n"`. Embedded tabs/newlines/quotes/backslashes remain valid through standard JSON escaping. Multiple files are an array, not a delimiter convention. Generate IDs with an existing suitable helper or Node's built-in facilities; do not add `uuidv7` or `printable-binary` dependencies.

### Memory lessons

Preserve the useful, human-readable convention from the memory skill: `MEMORIES/<descriptive-name>.frontmatter.md`, with exactly `description`, `datetime`, and `tags` in the frontmatter and the lesson in the body. Generate a timezone-aware timestamp in code, following the skill's local-time convention for new lessons; preserve existing timestamp representations on read.

The reflector supplies the description, tags, and body. Code generates safe filenames and serialized metadata. Do not overwrite a different existing lesson on a title collision; choose a disambiguated name. No evidence section is required. The skill's validator can be used as a compatibility check, not a runtime dependency.

## 4. Upstream-friendly architecture

Evaluate these alternatives before changing upstream files:

| Alternative | Assessment |
|---|---|
| Standalone Pi extension only | Suitable for storage/retrieval, but current code exposes no hook into the reflector's internal prompt/tools. Reading plain reflections afterward cannot reliably recover all desired structured outputs without another inference pass. |
| Wrapper that copies/replaces the reflector or intercepts its model transport | Avoids some textual edits but duplicates behavior or relies on internals; reject unless a genuine supported seam appears upstream. |
| Small optional reflector hook plus feature modules | Preferred with the current source: one existing reasoning loop, most custom behavior in new files, and an unchanged disabled path. |

Implemented area: `src/durable-memory/`, containing contracts, configuration, extra prompt/tools, buffered capture, persistence, and retrieval/registration. Split by responsibility only as needed; do not build a general plugin framework. Add dedicated tests under `tests/` and use this document as the design reference.

Upstream touchpoints used:

- `src/agents/reflector/agent.ts`: optional extra instructions/tools and enough completion information to release a successful attempt's buffered outputs. Preserve the default prompt, tool list, return behavior, and existing reflection validation when disabled.
- `src/hooks/consolidation-trigger.ts`: supply the optional integration and release exports after existing cancellation checks, outside the model fallback boundary. Session/branch ownership checks do not currently exist upstream; the new feature layer must supply them.
- `src/index.ts`: register the feature and its retrieval surfaces.
- Configuration stays in the new `src/durable-memory/config.ts`: a separate namespace keeps durable-file scope out of upstream session-memory settings. No upstream `Config` or `Runtime` changes were needed.
- `dist/index.ts`: regenerate through the existing build, never hand-edit it.

Leave observer/dropper implementations, ledger formats/projections, token accounting, compaction hooks, and the original reflector prompt unchanged unless inspection reveals a concrete necessity. Small justified changes are allowed; zero upstream edits is not a goal in itself.

## 5. Capture and persistence flow

1. The optional `prepareReflector` hook creates a fresh attempt-scoped `ReflectorPass`. Its addon supplies `record_decisions` and `record_lessons` alongside `record_reflections`, supplementary instructions, the configured project root, and a clean-completion callback; its `flush()` releases eligible outputs outside model retry handling.
2. Supplemental guidance distinguishes session reflections, path-bound decisions, and reusable lessons. It allows none, either, or both export types, trusts the observer/reflector's judgment and attribution, skips routine activity, and does not request raw-source verification. Existing source-ID requirements for ordinary reflections remain unchanged.
3. Tool execution validates structural shape and buffers outputs in memory; it does not immediately mutate project files. Allocate a fresh buffer per primary/fallback attempt.
4. Release only the successful attempt's exports after checking cancellation and that the project/session/active-branch origin is still applicable. A failed/aborted attempt must not leak disk writes. Current reflector behavior may retain partial session reflections after a stream error; do not change that upstream behavior, but do not treat it as proof that exports completed successfully.
5. Export-only output is valid even when no new session reflection is emitted. Keep this outside the existing `if (!reflections) return` gate. It must not advance reflection coverage or unlock the dropper.
6. Persist through ordinary code with bounded serialization/locking for cooperating writers, safe paths, and collision-safe memory-file creation. Never let a model-provided filename choose an arbitrary output location.
7. Report write failures separately. They must not trigger a fallback model call, discard valid reflections, or block compaction. Partial success across ADR and lesson files is allowed and should be reported; a transaction spanning both stores is not required.

Structural policy is shared by capture, storage, and retrieval through `src/durable-memory/types.ts`; provider-facing schemas do not replace those shared guards. This is format validation, not factual verification.

There is no existing-history scan in capture. Cheap exact-repeat suppression within the current batch/session is reasonable; semantic deduplication and cross-session reconciliation are deferred. Do not promise crash-safe exactly-once delivery. Bounded ADR locking deliberately does not steal existing locks: a process crash can require manual stale-lock removal. This operational limitation is documented, not treated as automatic recovery; adding a safe recovery mechanism remains separate work. Additional tool output can consume more tokens/turns within the existing loop; this is not a second extraction worker or a free operation.

## 6. Retrieval without a required skill

### Decisions

Build a lightweight, cached path lookup from `ADR.jsonl`, refreshing on file changes. This read/index work belongs to retrieval, not to the reflector's capture path. Return bounded, dated history with attribution; flag additional matches rather than injecting the entire log. A newer date alone must not erase unrelated older decisions for the same file. Malformed rows should produce a diagnostic without making every file operation unusable.

Surface relevant records while the agent reads/plans changes. The crew verified that Pi's `tool_call` happens after the model selected an edit; nested callers may catch child errors or suppress results, and sibling calls do not create an intervening model request.

The selected first-version implementation is advisory: annotate successful supported file-read results and provide `memory_lookup` with concise agent guidance. Registration owns a single lifecycle epoch shared by capture and retrieval; readers do not maintain a competing set of session invalidation events. Do not add an edit/write gate, a context-first retry protocol, or exposure-tracking state merely to imply a guarantee the host cannot provide for arbitrary nested code. This keeps the user’s low-criticality feature small.

Read annotations can inform a subsequent model turn, but not a sibling edit already selected in the same response; nested annotations are visible only when the caller forwards them. Direct edits without prior reads/lookups, shell commands, and third-party mutation tools are not automatically protected. Matcher/reader failures fail open with a diagnostic. Test and document these limits rather than claiming universal pre-edit enforcement.

The coding agent's rule is: preserve human-attributed decisions by default; do not silently override or routinely relitigate them; when the user's task conflicts, explain the conflict and ask whether to keep or review. Routine compliant edits do not require confirmation. Treat retrieved bodies as historical data, not arbitrary executable instructions.

### Lessons

Expose a metadata-first lookup of configured project/shared memory roots by filename, description, and tags. Read bodies only when relevant, with bounded results. Add the necessary tool guidance or startup metadata discovery so the coding agent can use this without loading the old skill; do not introduce another relevance-classification model or a vector database.

Prompt guidance should discourage re-exporting retrieved records as new discoveries. Best-effort selection and cheap exact-repeat suppression are sufficient for this version.

## 7. Acceptance tests and delivery

Add focused tests for:

- Disabled feature: unchanged reflector prompt/tools, no artifact writes or memory-history reads, and existing pipeline behavior preserved.
- Enabled run: reflections, ADRs, lessons, both export types, zero output, and export-only output; no separate extraction loop is launched.
- JSONL roundtrips: multiline text, quotes, tabs, backslashes, Unicode, and multiple paths; no custom encoder needed.
- Memory output: valid three-field frontmatter, safe/collision-resistant filenames, no silent replacement, and compatibility with metadata-only lookup.
- Primary failure followed by fallback; abort and stream-error paths; session/root/branch replacement; filesystem errors isolated from model retries and memory coverage.
- Exact-repeat handling and concurrent cooperating writers; no retrospective capture scan or inferred status updates.
- Path lookup sensitivity/specificity: exact match, multiple files, near-miss names, absolute/relative normalization, and out-of-root rejection.
- Bounded retrieval, malformed records, no-match silence, read-result annotation and content preservation, metadata/body scope boundaries, and cache reset after session/project changes. Verify that no mutation gate or universal nested/parallel visibility guarantee is introduced.
- Prompt-level human-attribution policy and privacy/scope rules. These tests check instructions and data flow, not factual correctness of arbitrary model-generated claims.

Initial delivery verification on 2026-10-26 passed all 617 tests, typecheck, build, generated-bundle smoke tests, and correctness/maintainability re-review. Tests used a fake model transport with the real agent loop, capture, file writes, and retrieval; no live model was called. Stale-lock recovery remains the documented v1 limitation.

For subsequent changes, run focused new tests, then `npm test`, `npm run typecheck`, and `npm run build`. Review the generated bundle and the remaining upstream-file diff. Use mocked models and temporary memory roots for automated tests; any live-model smoke test should be explicitly arranged rather than write into real shared memory by default.

Update normal documentation with enablement, storage locations, retrieval limits, approximate capture dates, accepted attribution uncertainty, and the intentionally deferred maintenance work. Ensure documented files are accessible in the package/repository layout. The system must work without shipping or loading the original capture skill.

Do not delete or migrate the supplied `ADR.tsv`, `ADR_DESIGN.md`, or `memories/`, and do not edit the globally installed skill as part of this implementation. Start new writes in `ADR.jsonl`; any migration or retirement of existing material is separate, approved work. Do not stage or commit changes.
